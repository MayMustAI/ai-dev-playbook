# 실시간 채팅 (Slack 기준, Teams·Discord에도 적용)

## 찾는 방법

Slack MCP 도구는 구현마다 다르다. 쓸 수 있는 Slack MCP와 도구 스키마를 먼저 확인한다. 인증이 필요하거나 실패하면 멈추고 빈틈으로 보고한다. 검색·조회 도구만 쓰고, 메시지를 보내거나 반응을 남기는 도구는 쓰지 않는다.

1. **작성자와 기간으로 좁히기.** PR이 머지된 날짜 전후의 PR 작성자 메시지를 찾는다. 범위가 크게 줄고 핵심이 나오는 경우가 많다.
2. **PR 링크 검색.** PR은 리뷰나 논의 중에 채팅에 링크되는 경우가 많다. PR URL이나 `/pull/<번호>`로 찾는다.
3. **오류 문자열 검색.** 코드가 특정 오류를 처리하면 그 문자열로 찾는다. 장애 스레드가 나오는 경우가 많다.

## 흔한 함정

- **보존 기간.** 아주 오래된 메시지는 보존 정책으로 사라졌을 수 있다. 특정 날짜 이전이 전혀 나오지 않으면 그 경계를 기록한다.
- **DM.** 많은 결정이 검색할 수 없는 DM에서 일어난다. 알려진 한계로 적는다.
- **농담을 결정으로 오인.** 채팅은 가볍다. "그냥 그거 해"는 커밋 직전에 있었더라도 결정이 아니다. 숙고한 논의를 찾는다.
- **맥락 없는 단일 메시지.** 스레드 없이 읽으면 뜻이 달라지는 경우가 많다. 항상 스레드 전체를 가져온다.
- **인증 실패.** MCP 인증이 안 되어 있으면 멈춘다. 결과를 지어내지 말고 Slack을 조사하지 못했다고 보고한다.

## 돌려줄 것

관련 메시지·스레드마다:
- 채널, 작성자, 날짜
- 원문 인용과 링크(퍼머링크가 있으면)
- 스레드에서 이어진 결론이나 반대 의견
