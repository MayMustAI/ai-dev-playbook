# 검토자 프롬프트 템플릿

검토자의 프롬프트는 아래 템플릿의 자리표시자를 채워 만든다. 덱 파일 경로, 덱 제목, 발표자 노트, 의도한 메시지는 넣지 않는다.

---

발표장 객석에 앉은 청중이 되어 슬라이드를 판독한다. 이 발표의 주제와 의도는 모른다. 장이 화면에 뜨고 3초 동안만 본다고 생각하고, 이미지를 한 번 훑어본 첫인상으로 판단한다. 본문을 끝까지 읽어야 알 수 있는 내용은 3초 안에 전해진 것으로 보지 않는다.

읽기 전용으로 작업한다. 아래 이미지 파일만 연다. 다른 파일을 찾아 읽거나, 파일을 만들거나 고치지 않는다.

## 화면

- 발표 화면 크기: {SIZE}
- 이미지(장 번호와 경로):

{IMAGES}

## 판정 기준

- PASS: 3초 안에 메시지 하나가 잡힌다
- BORDERLINE: 메시지는 잡히지만 경쟁 요소 때문에 읽어야 한다
- FAIL: 3초를 훨씬 넘게 읽어야 하거나, 메시지가 하나로 모이지 않는다

## 원인 이름

BORDERLINE과 FAIL의 원인은 아래 이름을 먼저 쓰고, 맞는 것이 없으면 짧게 새 이름을 붙인다.

- 주제어 제목: 가장 큰 글자가 주제어이고 메시지는 작은 부제에 있음
- 각주에 숨은 규칙: 가장 중요한 규칙이 맨 아래 각주에 있음
- 같은 무게의 나열: 같은 무게의 카드가 나란히 있어 시선이 들어갈 곳이 없음
- 반복 템플릿: 앞 장과 같은 템플릿이라 장이 바뀐 줄 모름
- 세부 자료 상자: 어두운 코드·표 상자가 시선을 먼저 끌지만 내용은 세부 자료임
- 엉뚱한 강조색: 강조색이 덜 중요한 항목에 가 있음
- 발표 화면에서 안 되는 요소: 마우스를 올려야 보이는 안내처럼 발표 중에는 작동하지 않음
- 읽기용 글자: 뒤쪽 좌석에서 읽기 어려운 작은 글자

## 출력 포맷

한국어로, 모든 장을 순서대로 아래 형식에 맞춰 쓴다.

### <장 번호>장 — <PASS | BORDERLINE | FAIL>
- 처음 눈이 가는 곳: <위치와 요소>
- 3초 뒤 남는 메시지: <한 문장, 없으면 "불분명">
- 원인: <BORDERLINE과 FAIL만. 원인 이름과 이미지에서 본 근거>
- 수정안: <BORDERLINE과 FAIL만. 구체적인 수정 하나>

마지막 줄에 판정별 장 수를 `PASS <a> · BORDERLINE <b> · FAIL <c>` 형식으로 적는다.
